# 统一会话历史（实验功能）

此功能在独立功能分支验证，默认关闭。启用后，AxonHub将Responses成功终态的输入与输出、原生压缩来源和本地桥接来源保存为与请求日志独立的加密历史。对话分支由明确响应ID或检查点引用确定，不按线程查找“最近一次对话”。

```yaml
unified_history:
  enabled: true
  retention_days: 0
```

也可设置 `AXONHUB_UNIFIED_HISTORY_ENABLED=true`。配置在启动时读取；不要在没有部署计划时重启服务。`retention_days: 0`不自动清理历史，须自行规划存储容量；设为正整数后，超过该天数未被写入或有效读取的记录不可读取，定时GC在额外一天宽限后删除。该策略独立于请求日志清理；过短保留期可能让旧检查点的原文来源失效。关闭功能不删除已经保存的记录。

## 数据与恢复

每条原始输入/输出按64KiB块存储，内容哈希只在同一项目/API Key范围内去重。清单保留顺序、重复项、完整工具参数与结果。清单、块和引用分别绑定归属与标识加密；已有值不可被同ID的另一个分支覆盖。一次事务发布所有块和清单并核对最终引用，冲突会回滚，不向普通系统缓存装入大历史。单快照最多64MiB，清单最多4MiB，分批查询与写入限制SQL参数数量。

归档来源来自客户端的原始请求，独立于发往上游的摘要视图。新检查点在可验证时展开旧来源后保存，避免连续压缩不断累积祖先层数。

完整响应可在请求日志删除、进程重启后作为WebSocket增量或HTTP续接的来源。原生与本地检查点都使用同一分块存储；旧密封摘要与旧原生来源仍可读取。没有捕获到的旧历史不会凭空补全。日常成功请求的归档错误会记录告警；发布压缩检查点的来源保存失败则阻止该检查点发布。

## 上下文组装

原生/auto渠道继续优先使用可接受的原生状态。明确匹配的检查点解密拒绝单独保留30分钟，不冒充恢复成功证据；相同归属、线程、模型、目标渠道和凭据下，即使重连改变了窗口标识，也不会再次发送同一个已拒绝检查点。恢复仍验证原始来源，不因拒绝记录而直接丢弃检查点。发生明确拒绝或选择本地桥接时，统一恢复尝试展开保留的原始来源，验证归属、保留前缀有序匹配、工具配对、模型/指令/工具契约、16代与64MiB边界。先与直接来源对齐，再展开祖先；支持Codex重新插入当前运行说明和更新工具定义。普通消息仅在完整可见内容相同时忽略重分配的ID，工具标识和参数不变。同一消息ID对应不同内容仍拒绝恢复。

已知模型窗口是组装前提。优先使用已配置模型窗口；直接渠道路由没有模型条目时，按实际目标模型精确查找程序内置目录，不在请求中联网取目录，也不猜测未知别名。输入预算使用上下文的四分之三与1MiB的较小值，文本按JSON字节保守计量，每张完整图片另预留16KiB预算；图片本体原样保留，Base64传输体积不当成文本token。私有文件引用、未解密工具参数等不支持项保留兼容路径。

- 可容纳时直接使用原文，不调用模型总结。
- 历史过长时，按已完成的交互组成最多128KiB预算的稳定区段，长用户回合可在工具调用与结果完整闭合后分段；保留全部原始user/system/developer消息、增长尾部及最近完整交互。
- 已经由后续交互确定边界的较早区段分别生成摘要；仍在增长的末尾区段保留原文，避免每轮重复总结相互重叠的尾部。摘要按区段原文、模型、指令、工具与推理参数复用。摘要输入始终是原始区段，不使用另一份摘要作为唯一来源。
- 最多处理32个区段；缺失2个及以上区段时最多4路并发，取消后剩余的少量区段也按同样规则处理，各自隔离请求上下文。全部由原样保留的user/system/developer记录组成的区段，不再生成多余摘要。完成的区段持久化复用，取消后不再启动后续区段。区段请求日志包含`X-Axonhub-Unified-History-Segment`，该内部标识不发给上游。未知预算、不可分割的超大工具交互或超过32个区段会使用原有兼容路径。已经开始的生成失败不会自动再开启一套总结；上下文装不下也不会截去用户约束。
- 有剩余预算时，以当前用户文本做确定性关键词匹配，恢复相关区段的完整原文，保留工具配对。Codex结构化问题回复仅以实际问题和答案参与检索，排除包装中的工具名、请求标识；原始用户回复不变。中文夹杂代码时可提取完整代码标识；至少3个区段中半数及以上都出现的泛词，不单独触发原文回填。它不是完整语义检索，也不会给客户端注入一个无法执行的历史工具。
- 本地检查点在组装完成后直接密封输出，不再调用模型总结已组装结果。区段模型请求各自记录usage，本地组装的模型usage明确为0。

通用视图中的完整消息去除旧上游传输ID、status和诊断旁带字段，工具call_id与参数保持不变，原始归档不变。原始用户修正按时间顺序保留，网关不自行猜测哪些要求已失效。摘要作为assistant材料引用，不将工具输出提升为system/developer指令。恢复的文本在发送或生成摘要前重新通过现有提示词保护策略。

## 质量与成本边界

同一目标成功接收组装后的上下文后，网关另存该实际发送视图。普通全量重发先按原始输入前缀、项目/API Key、线程、窗口、检查点、目标模型/端点/API凭据或OAuth账户和请求契约核对视图，然后保留此前的输入并追加新记录，不因尾部增长或最新问题变化重新总结旧窗口。请求保护仍重新执行；显式修改输入或契约不能被旧视图覆盖。失败或取消的请求不会发布成功视图。只有编译视图首次成功时持久保存，使用同一分块存储，不替换原始归档；正常模型窗口限制和客户端压缩流程仍适用。

升级时可在最多128条近期完成的目标渠道执行记录中寻找旧视图，核对完整原始前缀、账户或唯一凭据后缀及已有加密摘要后导入。该查找不是按线程直接采用最新记录；找不到可验证来源时继续原有恢复路径。同一OAuth账户刷新令牌不改变已接受文本视图的身份，也不因渠道更新时间变化排除最近6小时的已验证升级来源；换账户仍隔离。日志删除前已导入或新发布的视图可在重启后复用。

摘要身份会规范化JSON对象字段顺序，保留数组顺序、字符串和数值。历史生成留下的常见字段排列仍可读取，别名指向既有摘要及其原始来源标签，避免仅因升级或序列化变化重新付费总结。

存储原文无损不等于每轮模型看到了全部原文。长历史仍使用模型摘要；关键词检索不能保证找到全部相关材料。跨资源时，原生推理密文原样留在归档，但通用视图只带可见推理摘要；日志明确记录未移植的私有推理项数量。网关无法解密或保证迁移供应商未公开的推理状态。加密工具参数不适用该例外，不能为了成功请求而丢掉。

冷区段首次总结仍会消耗token和等待时间；它的收益需要靠后续复用验证。压缩导致前缀变化、目标上游账户变化等仍可能降低缓存率。本功能不降低模型或推理强度，不以缓存百分比代替总成本和任务质量。

上线验收应比较原始输入/区段摘要/当前可见原文、实际生成次数、cached_tokens、首字与总耗时，并用早期约束、数值、代码、工具结果、后续纠正和分支隔离用例验证质量。CI使用合成材料和本地模拟上游，不证明真实模型回答质量完全无损。
