# 检查点续接与会话档案

AxonHub 现在以客户端当前检查点及其后的消息继续会话。此前统一历史的自动组装器、分段模型摘要、已接受视图改写和合成压缩执行器已经移除。成功的压缩必须产生可继续使用的紧凑窗口；网关不再把序列化的原始历史冒充摘要返回。

## 原生检查点与可移植检查点

原生检查点是不透明状态，归生成它的上游资源所有。AxonHub 保留其内容和客户端留下的消息。普通续接不会展开更早的检查点，也不会启动摘要请求。

当前目标明确拒绝原生检查点时，AxonHub 直接执行一次检查点恢复，不再先删除可选消息 ID、携带同一密文重发一次。恢复使用该检查点保留的来源生成一份有大小上限的可移植摘要，按项目、API Key 和检查点身份持久保存，同时保留当前窗口已有的消息以及检查点之后的工具调用和结果。重连、进程重启后复用保存的摘要。

这次拒绝还会为当前线程、模型和渠道配置建立可移植压缩约定。后续压缩请求使用当前窗口，通过普通 Responses 请求生成可移植摘要，不再重复尝试原生压缩、再恢复整份原始历史。新线程或操作员修改渠道配置后建立新的约定。显式配置为本地桥接的渠道也使用这条单份摘要路径。

可移植检查点采用 AxonHub 认证封装。经由同一 AxonHub 实例发送时，它会变为普通摘要消息，上游不需要理解 AxonHub 的格式。封装仍绑定项目、API Key 和实例密钥，并非所有供应商都能读取的原生密文；不能直接交给无关网关使用。

## 压缩边界

- 客户端决定何时请求压缩。AxonHub 处理该请求，或首次明确不兼容的原生检查点迁移；不会给每个普通推理请求重新做摘要。
- 当前规范窗口是下一检查点的来源。之前的可移植摘要继续作为摘要使用，不恢复成其压缩前档案。
- 独立 `/responses/compact` 的输出作为完整后续窗口保留。原生输出及不透明项按上游结果保存。
- 可移植摘要以最多 4,096 token 为提示目标，发布前还必须满足 64 KiB 文本上限。过大或不完整的摘要不会取代之前的上下文。
- 目标供应商按实际渲染内容校验上下文容量。AxonHub 不再用 JSON 字节数、近似分词器或百分比余量拒绝摘要请求。模型选择、工具转换与渠道覆盖仍然生效；完整原文向选定供应商发送一次。若上游确实返回超窗错误，直接返回该错误，不重复发送相同摘要请求。
- 迁移可以读取已认证的旧来源，但不拆成多份模型摘要。来源缺失、不匹配或过大时，在发布替代检查点之前给出具体错误。

## 独立档案

原始请求记录和检查点来源窗口继续加密保存，并绑定项目与 API Key。旧的不可变记录继续保留；升级不会删除数据库或改写历史密文。

档案用于诊断、重连恢复和明确的迁移，不会在每次压缩后自动重新发送。新检查点来源以带版本的身份保存实际当前窗口；读取路径继续兼容旧来源记录。

摘要保留有用的任务状态，不等于保留每一个原始 token 或供应商的隐藏推理。档案完整不代表模型记忆无损。原生来源缺失时，需要由能读取它的资源继续，或提供明确交接内容；静默删除不透明状态会造成上下文丢失。

## 重试行为

原渠道的自动会话标识轮换及其重发逻辑已移除。已知模型容量耗尽错误停止同渠道重试；其它允许的独立渠道仍可参与选择。检查点恢复只做一次请求修正，不重复发送已被拒绝的相同检查点，也不靠恢复越来越大的完整历史来使请求表面成功。

模型目录解析、Codex Lite `additional_tools` 到 Responses `tools` 的规范化与检查点续接独立处理。
