# Responses 延迟与兼容性

## 首字超时

现有的「流式首字超时」现在等待有效输出，包括文本、推理、工具调用或支持的媒体输出。
`response.created`、只有角色的初始化包不再提前解除计时。终止响应仍正常结束；设为 0 则关闭超时。
配置和 API 字段名不变。

在尚未提交输出前，配置的重试规则可以切换尝试；有效输出开始后，该超时不再中断响应。

## 流式保活

SSE 保活默认启用，间隔 15 秒。OpenAI 兼容流使用 SSE 注释，Anthropic 兼容流使用协议 ping。
心跳不是模型输出，也不会计入计费 token。保活从流式处理器拿到上游流后开始，
不覆盖连接建立或首字前的重试探测阶段。

可以显式关闭：

```yaml
server:
  sse_keep_alive:
    enabled: false
```

## Codex 中转内部元数据兼容

部分 Responses 中转拒绝新版 Codex 的 `internal_chat_message_metadata_passthrough`。
只有上游 HTTP 或有效输出前的流式 400 明确指出该字段未知或不支持时，AxonHub 才移除内部元数据。
消息正文、工具、加密压缩历史和 prompt cache key 均不变。仍受正常重试预算限制，
首次恢复需要至少允许一次同渠道重试。

拒绝能力保存在有界进程内缓存中，有效期六小时，按渠道、端点、模型和凭据哈希隔离。
后续请求避免已知无效的往返；其他端点和凭据仍保留原生元数据。泛化 400 不触发兼容逻辑。

## 加密推理被拒绝后的恢复

默认保留加密推理，遵循[官方无状态续接指引](https://developers.openai.com/api/docs/guides/deployment-checklist#use-reasoningencrypted_content)。
只有 Codex 渠道明确返回 HTTP 或有效输出前的流式 400 且 `error.code` 为 `invalid_encrypted_content` 时，
才允许在同渠道重试中依据保留的显式历史重新推理。这是降级恢复，不是解密，也不是隐藏推理的无损恢复。

恢复要求存在用户历史，且函数/自定义工具结果有对应的先前调用。
没有 `call_id` 但具名的独立函数结果保持有效；非空却找不到对应调用的 `call_id` 仍拒绝恢复。
存在未展开的 `previous_response_id`、压缩项、条目引用、加密代理消息/参数或未知输入类型时拒绝恢复。
只替换带密文的推理项：可见摘要和推理文本转为助手文本；
消息、工具输入/结果、原生工具 ID 和缓存键不变。未知摘要或内容类型直接报错，不静默丢弃。

该规则仅作用于当前请求及渠道，不会全局禁用后续请求的加密推理。
泛化校验错误不触发；恢复仍消耗既有的同渠道重试预算。

## 会话回放缓存

原生 Responses 快照现在记录实际出站输入以及下游转换前的上游输出。
内存未命中后，优先恢复已认证请求对应的成功执行快照，而不是原始 WebSocket 增量，
保留完整历史以及原生 `msg_`/`fc_` ID。回放时移除已知的网关生成消息 ID、
与 `call_id` 相同的函数调用 ID；调用关联、原生 ID 和加密推理内容保持不变。
仍引用前序响应的未展开历史增量不会被误当作完整上下文。

对于回放大小限制内的流式响应，原生快照由上游流生产者在终止事件分发给透传客户端之前发布。
客户端立即发送工具结果续接时，不再等待独立流水线消费者或数据库完成落库；
合成的 Codex 终止事件也遵循相同顺序。
辅助的 1 MiB 原始事件缓冲溢出后，仍能从终止快照或已完成的原生条目恢复；不会无界缓存事件流。

热缓存继续保持两小时 TTL、最多 2,048 条/64 MiB 总量；单条完整历史上限与持久化回放统一为 16 MiB，
大历史立即续接不再依赖数据库完成时序。
历史确实无法恢复时，Codex HTTP 回退返回 `previous_response_not_found`，不会静默移除引用后发送孤立工具结果。
客户端应按[官方 WebSocket 指引](https://developers.openai.com/api/docs/guides/websocket-mode#fork-a-conversation-onto-a-new-stream)重放完整输入。
按时间有序淘汰，避免每次查询遍历所有记录；存储快照不可变，大拷贝移出共享锁；
批量复制减少逐条分配，同时限制每条切片容量，防止追加数据覆盖相邻记录。
这些是网关自身开销优化，不代表承诺某个供应商的首字延迟或缓存命中率。

远端 Test CI 执行定向 race 测试并发布 `responses-cache-benchmarks` 基准产物。

## 已压缩对话切换到本地桥接

渠道远程压缩策略设为 `local_bridge` 后，已有远程压缩对话可以根据保留的原始请求重建。
如果源请求包含更早的压缩项，先生成或复用早一代摘要，将其替换回源请求，再生成当前代摘要。
不会直接删除不透明压缩项，因为[官方压缩协议](https://developers.openai.com/api/docs/guides/compaction)中的这些条目承载会话状态。

来源未保留、出现循环或超过 16 代时停止恢复。
摘要生成会去重，但不会在同一个 singleflight 操作内等待递归的更早代生成。
内部摘要请求同样支持明确的元数据/推理密文拒绝恢复，并共享已配置的同渠道重试预算。
同一个摘要请求若先后遇到两种拒绝，需要两次同渠道重试；不会自动修改重试设置。
启用请求持久化时，每次实际的上游尝试分别记录执行结果。

重启后按精确压缩键查找保留摘要，同时覆盖 HTTP 与 WebSocket 请求格式，不受模型切换和最近历史扫描上限影响。
内存摘要及生成去重锁均按已认证 API Key 和项目隔离。
源历史确实缺失时记录 `compaction_history_unavailable` 400，不再返回没有请求记录的泛化 500。

## 上游临时限流

有效输出开始前的 HTTP/Responses 流式 429 与 503 临时过载错误使用同一重试策略。
存在其他物理渠道时优先切换；最后一个渠道遇到临时限流时，允许使用已配置的同渠道重试预算，
包括 trace 粘性候选。配置五次重试、默认一秒基础间隔时，采用 2、4、8、16、32 秒退避，
每次另加最多 500 毫秒随机抖动。更长的系统重试间隔，以及受支持的 `Retry-After`
（秒数或 HTTP 日期）、`retry-after-ms`、`x-ms-retry-after-ms` 等待提示优先。

明确配额耗尽、本地准入限流、上游要求等待超过一分钟时，不启用同渠道限流重试。
取消请求会立即打断退避。已经提交文本、推理或工具输出后不重新尝试，避免重复输出或工具执行。
现有重试次数仍为硬上限，持续上游限流最终仍返回错误；不会自动修改系统重试设置。
客户端和代理超时需要容纳额外等待，流式心跳不覆盖这一首字前重试阶段。

来自对端的 HTTP/2 `INTERNAL_ERROR` 和 `REFUSED_STREAM` 重置也可在有效输出提交前重试，覆盖最后一个粘性渠道。
本地取消及协议错误不当作这类临时重置。WebSocket 错误支持 `status_code` 别名及标量请求头值，
流式和同步错误转换都保留 `Retry-After`。新增余额、支出与用量耗尽错误映射为 429，但不会进行无效同渠道重试。

## GPT-6 Astra 流式兼容

继续保留异步函数/自定义工具身份、steering、配置更新及缓存控制。
自定义工具输入只在 `response.custom_tool_call_input.done` 中提供时，补发缺失后缀且仅发一次；
重复或空 done 事件不会清空或重复已发输入。最终输入与已发前缀冲突时明确报错，不执行被改变的命令。

执行日志中的泛化中转错误补充结构化 `code` 和 `param`。最终尝试成功不会删除前面的失败记录；
历史记录只有 `bad response status code` 时，不能据此判断为远程压缩故障。

## Claude Code 身份版本

离线回退版本更新为 2.1.263。设置经过校验的环境变量
`AXONHUB_CLAUDE_CODE_VERSION=2.1.263` 可固定网关生成的身份版本并跳过自动发现。
真实客户端 User-Agent 仍被保留，已有渠道请求头覆盖规则仍优先。非法版本值被忽略；
不固定版本时继续异步查询官方 release，不阻塞请求首字路径。
