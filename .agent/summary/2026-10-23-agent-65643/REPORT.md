## 本地缺陷

1. checkpoint recoveryKey只查看原始客户端小请求，要求其中有checkpoint；已认证展开的增量历史未被使用。导致#65643恢复漏过，直到客户端完整重发才生成摘要。
2. 泛化资源不匹配同时触发普通ID删除与checkpoint摘要。对于含reasoning ID的原生窗口，没有先尝试保留全部密文、仅去存储ID的已有兼容方向。
3. #65644替换checkpoint后，渠道级历史策略自动删除后续108个reasoning。该策略可由#65443、#65447的失败/成功正文对推导，并非本次reasoning拒绝。窗口由286项变成178项，改变缓存前缀；原缓存键不变不能保住不同内容的缓存。
4. reasoning成功缓存用ID+密文哈希差集，单纯去ID也会被误记为reasoning删除，可能影响下次完整回放。

## 修复

- 从认证成功的完整Responses snapshot准备出的effective body绑定delta检查点，仍比较原checkpoint/owner/current previous，不信任出站override作为来源。

- 已接受同目标snapshot和checkpoint后续窗口不套用其他请求的全量明文策略。本请求明确拒绝及精确内容的成功规则仍有效。
